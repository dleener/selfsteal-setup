# selfsteal-setup

Скрипт настраивает SelfSteal для Xray Reality в панели 3x-ui: вместо чужого домена (`cloudflare.com`, `wp.pl` и т. п.) Reality начинает предъявлять сертификат вашего собственного домена.

Зачем: хостеры (например, Hostoff) считают нарушением, когда на TLS-порту сервера показывается чужой сертификат. С SelfSteal сканер видит обычный сайт на вашем домене с настоящим сертификатом Let's Encrypt.

## Что делает скрипт

1. Проверяет, что домен указывает на этот сервер
2. Ставит nginx и certbot
3. Создаёт страницу-заглушку и выставляет её на порт 80
4. Получает сертификат Let's Encrypt (с автопродлением)
5. Поднимает nginx с TLS на `127.0.0.1:8001` — сюда будет смотреть Reality
6. Настраивает перезапуск nginx после каждого продления сертификата
7. Проверяет результат и печатает, что вписать в 3x-ui

Правку в самой панели 3x-ui скрипт не делает — это два поля, их надёжнее поменять руками.

## Требования

- Ubuntu 22.04 / 24.04 или Debian (нужен `apt`)
- Доступ root
- Свободный порт 80 (или занятый nginx)
- Домен, которым вы управляете

## Перед запуском: DNS-запись

В панели управления доменом создайте запись:

| Поле | Значение |
|---|---|
| Тип | A |
| Имя | поддомен, например `nl2` |
| Содержимое | IP сервера |
| Proxy (Cloudflare) | **DNS only** — серая тучка |

Оранжевую тучку не включать: тогда Let's Encrypt увидит Cloudflare, а не ваш сервер, и сертификат не выдастся.

Проверить, что запись разошлась:

```bash
dig +short nl2.proxhub.tech
```

Должен вернуться IP сервера.

## Запуск

Одной командой, без скачивания:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/ЛОГИН/selfsteal-setup/main/setup-selfsteal.sh) \
  -d nl2.proxhub.tech -e you@example.com
```

Или через клонирование:

```bash
git clone https://github.com/ЛОГИН/selfsteal-setup.git
cd selfsteal-setup
bash setup-selfsteal.sh -d nl2.proxhub.tech -e you@example.com
```

`ЛОГИН` замените на свой логин GitHub.

### Параметры

| Параметр | Обязательный | Что значит |
|---|---|---|
| `-d`, `--domain` | да | домен для сертификата |
| `-e`, `--email` | да | почта для уведомлений Let's Encrypt |
| `-p`, `--port` | нет | локальный порт для Reality, по умолчанию `8001` |
| `-n`, `--name` | нет | название на странице-заглушке, по умолчанию `ProxHub` |
| `--skip-dns-check` | нет | не сверять DNS с IP сервера (если сервер за NAT) |

## После скрипта: правка в 3x-ui

1. Откройте панель → **Inbounds**
2. Отредактируйте Reality inbound (карандаш)
3. В блоке **Reality** поменяйте два поля:

| Поле | Значение |
|---|---|
| Target / Dest | `127.0.0.1:8001` |
| SNI / Server Names | ваш домен, например `nl2.proxhub.tech` |

4. Ключи, shortIds и клиентов **не трогайте** — иначе у пользователей отвалятся подписки
5. Сохраните
6. Обновите подписку в клиенте (HAPP и т. п.) и проверьте подключение

## Проверка

С любой машины (порт — тот, на котором работает Reality):

```bash
echo | openssl s_client -connect 83.142.30.102:8443 -servername nl2.proxhub.tech 2>/dev/null \
  | openssl x509 -noout -subject -issuer
```

Правильный результат:

```
subject=CN = nl2.proxhub.tech
issuer=C = US, O = Let's Encrypt, CN = ...
```

Сервисы вроде Censys обновляют данные с задержкой в несколько дней, поэтому сразу после настройки они могут показывать старый сертификат. Ориентируйтесь на `openssl`.

## Повторный запуск

Скрипт можно запускать повторно на том же сервере с тем же доменом — он перезапишет свои файлы, а действующий сертификат не будет перевыпускать без необходимости.

Если раньше SelfSteal настраивался вручную и для этого же домена есть `/etc/nginx/conf.d/selfsteal.conf`, скрипт уберёт его в резервную копию `selfsteal.conf.bak-<дата>`.

## Несколько доменов на одном сервере

Каждому домену — свой локальный порт:

```bash
bash setup-selfsteal.sh -d a.proxhub.tech -e you@example.com -p 8001
bash setup-selfsteal.sh -d b.proxhub.tech -e you@example.com -p 8002
```

В 3x-ui у каждого inbound свой Target.

## Какие файлы создаются

| Файл | Назначение |
|---|---|
| `/var/www/selfsteal/index.html` | страница-заглушка для Reality |
| `/var/www/html/index.html` | та же страница на порту 80 (старая сохраняется как `.bak-<дата>`) |
| `/etc/nginx/conf.d/selfsteal-<домен>.conf` | nginx с TLS на локальном порту |
| `/etc/letsencrypt/live/<домен>/` | сертификат и ключ |
| `/etc/letsencrypt/renewal-hooks/deploy/reload-nginx.sh` | перезапуск nginx после продления |

## Откат

1. В 3x-ui верните прежние Target и SNI
2. Удалите конфиг и перезапустите nginx:

```bash
rm /etc/nginx/conf.d/selfsteal-nl2.proxhub.tech.conf
nginx -t && systemctl reload nginx
```

3. При необходимости удалите сертификат:

```bash
certbot delete --cert-name nl2.proxhub.tech
```

## Если что-то не так

**«Домен смотрит не на этот сервер»** — A-запись ещё не разошлась, указывает на другой IP или в Cloudflare включена оранжевая тучка. Если сервер за NAT и IP точно верный — добавьте `--skip-dns-check`.

**certbot не получает сертификат** — снаружи закрыт порт 80. Проверьте файрвол у хостера и `ufw status`.

**«Порт 8001 уже занят»** — выберите другой через `-p 8002` и его же укажите в 3x-ui.

**После правки в 3x-ui `openssl` показывает ошибку или старый сертификат** — проверьте, что Target именно `127.0.0.1:<порт>`, а SNI совпадает с доменом. Если всё верно, перезапустите xray: в панели кнопка **Restart Xray**.

**Клиенты не подключаются** — в клиенте не обновилась подписка, и он стучится со старым SNI. Обновите подписку вручную.
