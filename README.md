# selfsteal-setup

Скрипт настраивает SelfSteal для Xray Reality в панели 3x-ui: вместо чужого домена (`cloudflare.com`, `wp.pl` и т. п.) Reality начинает предъявлять сертификат вашего собственного домена.

Зачем: хостеры (например, Hostoff) считают нарушением, когда на TLS-порту сервера показывается чужой сертификат. С SelfSteal сканер видит обычный сайт на вашем домене с настоящим сертификатом Let's Encrypt.

Два режима:

1. **Под ключ** — для чистого сервера. Ставит панель 3x-ui, настраивает SelfSteal и сразу создаёт готовое подключение VLESS Reality. В конце показывает ссылку и QR-код для телефона.
2. **Только SelfSteal** — если панель 3x-ui уже стоит. Настраивает серверную часть, а два поля в панели вы меняете сами.

## Требования

- Ubuntu 22.04 / 24.04 или Debian (нужен `apt`)
- Доступ root
- Свободный порт 80 (или занятый nginx)
- Домен, которым вы управляете

## Перед запуском: DNS-запись

В панели управления доменом создайте запись:

| Поле | Значение |
|---|---|
| Тип | A |
| Имя | поддомен, например `nl2` |
| Содержимое | IP сервера |
| Proxy (Cloudflare) | **DNS only** — серая тучка |

Оранжевую тучку не включать: тогда Let's Encrypt увидит Cloudflare, а не ваш сервер, и сертификат не выдастся.

Проверить, что запись разошлась:

```bash
dig +short nl2.proxhub.ru
```

Должен вернуться IP сервера.

## Запуск

Зайдите на сервер по SSH под root и выполните:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/dleener/selfsteal-setup/main/setup-selfsteal.sh)
```

Скрипт покажет меню и задаст несколько вопросов. В квадратных скобках — значение по умолчанию, чтобы его принять, достаточно нажать Enter.

```
  1) Установить всё под ключ: панель 3x-ui + SelfSteal + готовое подключение
  2) Только SelfSteal для уже установленной панели 3x-ui
  0) Выход
```

## Режим 1: под ключ

Что спросит:

| Вопрос | По умолчанию |
|---|---|
| Домен | — |
| Почта для Let's Encrypt | — |
| Порт для подключения к VPN | `443` |
| Имя первого клиента | `user1` |
| Название сайта на заглушке | `ProxHub` |

Если домен ещё не указывает на сервер, скрипт не падает, а предлагает проверить ещё раз, ввести другой домен или выйти.

Что сделает:

1. Всё то же, что в режиме 2: nginx, сертификат, заглушка, nginx с TLS на `127.0.0.1:8001`
2. Поставит последнюю версию 3x-ui официальным установщиком со случайными логином, паролем, портом и адресом панели
3. Включит для панели HTTPS с тем же сертификатом Let's Encrypt
4. Создаст подключение VLESS Reality (`selfsteal-<домен>`): Target `127.0.0.1:8001`, SNI — ваш домен, свежие ключи
5. Проверит, что порт VPN предъявляет сертификат вашего домена

Что получите в конце:

- адрес панели вида `https://nl2.proxhub.ru:34567/AbCdEf.../`, логин и пароль
- ссылку `vless://...` и QR-код для клиента
- короткую инструкцию: поставить Happ, v2rayNG или Hiddify, отсканировать QR, подключиться

Всё это сохраняется в `/root/3x-ui-selfsteal.txt`. Посмотреть снова:

```bash
cat /root/3x-ui-selfsteal.txt
```

Никому не показывайте пароль от панели и ссылку подключения. Новых клиентов добавляйте в самой панели, в подключении `selfsteal-<домен>`.

Если панель 3x-ui на сервере уже стоит и ставилась не этим скриптом, режим 1 её не трогает и предлагает перейти в режим 2.

## Режим 2: только SelfSteal для готовой панели

Можно выбрать в меню, а можно запустить сразу с параметрами, без вопросов:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/dleener/selfsteal-setup/main/setup-selfsteal.sh) \
  -d nl2.proxhub.ru -e you@example.com
```

Или через клонирование:

```bash
git clone https://github.com/dleener/selfsteal-setup.git
cd selfsteal-setup
bash setup-selfsteal.sh -d nl2.proxhub.ru -e you@example.com
```

Что делает:

1. Проверяет, что домен указывает на этот сервер
2. Ставит nginx и certbot
3. Создаёт страницу-заглушку и выставляет её на порт 80
4. Получает сертификат Let's Encrypt (с автопродлением)
5. Поднимает nginx с TLS на `127.0.0.1:8001` — сюда будет смотреть Reality
6. Настраивает перезапуск nginx после каждого продления сертификата
7. Проверяет результат и печатает, что вписать в 3x-ui

Правку в самой панели 3x-ui в этом режиме скрипт не делает — это два поля, их надёжнее поменять руками.

### Параметры

| Параметр | Обязательный | Что значит |
|---|---|---|
| `-d`, `--domain` | да | домен для сертификата |
| `-e`, `--email` | да | почта для уведомлений Let's Encrypt |
| `-p`, `--port` | нет | локальный порт для Reality, по умолчанию `8001` |
| `-n`, `--name` | нет | название на странице-заглушке, по умолчанию `ProxHub` |
| `--skip-dns-check` | нет | не сверять DNS с IP сервера (если сервер за NAT) |

Без параметров скрипт запускает меню.

### После скрипта: правка в 3x-ui

1. Откройте панель → **Inbounds**
2. Отредактируйте Reality inbound (карандаш)
3. В блоке **Reality** поменяйте два поля:

| Поле | Значение |
|---|---|
| Target / Dest | `127.0.0.1:8001` |
| SNI / Server Names | ваш домен, например `nl2.proxhub.ru` |

4. Ключи, shortIds и клиентов **не трогайте** — иначе у пользователей отвалятся подписки
5. Сохраните
6. Обновите подписку в клиенте (HAPP и т. п.) и проверьте подключение

## Проверка

С любой машины (порт — тот, на котором работает Reality):

```bash
echo | openssl s_client -connect 83.xx.30.xx:8443 -servername nl2.proxhub.ru 2>/dev/null \
  | openssl x509 -noout -subject -issuer
```

Правильный результат:

```
subject=CN = nl2.proxhub.ru
issuer=C = US, O = Let's Encrypt, CN = ...
```

Сервисы вроде Censys обновляют данные с задержкой в несколько дней, поэтому сразу после настройки они могут показывать старый сертификат. Ориентируйтесь на `openssl`.

## Повторный запуск

Скрипт можно запускать повторно на том же сервере с тем же доменом — он перезапишет свои файлы, а действующий сертификат не будет перевыпускать без необходимости.

В режиме 1 повторный запуск берёт логин, пароль и порты из прошлой установки, не переустанавливает панель и не создаёт второе подключение — просто снова покажет ссылку и QR-код. Удобно, если установка оборвалась на середине.

Если раньше SelfSteal настраивался вручную и для этого же домена есть `/etc/nginx/conf.d/selfsteal.conf`, скрипт уберёт его в резервную копию `selfsteal.conf.bak-<дата>`.

## Несколько доменов на одном сервере

Каждому домену — свой локальный порт:

```bash
bash setup-selfsteal.sh -d a.proxhub.ru -e you@example.com -p 8001
bash setup-selfsteal.sh -d b.proxhub.ru -e you@example.com -p 8002
```

В 3x-ui у каждого inbound свой Target. В меню локальный порт подбирается сам: если `8001` занят, берётся следующий свободный.

## Какие файлы создаются

| Файл | Назначение |
|---|---|
| `/var/www/selfsteal/index.html` | страница-заглушка для Reality |
| `/var/www/html/index.html` | та же страница на порту 80 (старая сохраняется как `.bak-<дата>`) |
| `/etc/nginx/conf.d/selfsteal-<домен>.conf` | nginx с TLS на локальном порту |
| `/etc/letsencrypt/live/<домен>/` | сертификат и ключ |
| `/etc/letsencrypt/renewal-hooks/deploy/reload-nginx.sh` | перезапуск nginx после продления |

Дополнительно в режиме 1:

| Файл | Назначение |
|---|---|
| `/usr/local/x-ui/`, `/etc/x-ui/` | панель 3x-ui и её база |
| `/root/3x-ui-selfsteal.txt` | адрес панели, логин, пароль, ссылка и QR-код |
| `/etc/x-ui/selfsteal-setup.env` | данные установки для повторного запуска |
| `/etc/letsencrypt/renewal-hooks/deploy/restart-x-ui.sh` | перезапуск панели после продления, чтобы она взяла новый сертификат |
| `/var/log/selfsteal-3x-ui-install.log` | лог установщика 3x-ui |

## Откат

1. В 3x-ui верните прежние Target и SNI
2. Удалите конфиг и перезапустите nginx:

```bash
rm /etc/nginx/conf.d/selfsteal-nl2.proxhub.ru.conf
nginx -t && systemctl reload nginx
```

3. При необходимости удалите сертификат:

```bash
certbot delete --cert-name nl2.proxhub.ru
```

Если ставили в режиме 1 и хотите убрать панель целиком:

```bash
x-ui uninstall
rm -f /etc/letsencrypt/renewal-hooks/deploy/restart-x-ui.sh /root/3x-ui-selfsteal.txt
```

## Если что-то не так

**«Домен смотрит не на этот сервер»** — A-запись ещё не разошлась, указывает на другой IP или в Cloudflare включена оранжевая тучка. Если сервер за NAT и IP точно верный — добавьте `--skip-dns-check` (в меню — пункт «Продолжить без проверки»).

**certbot не получает сертификат** — снаружи закрыт порт 80. Проверьте файрвол у хостера и `ufw status`.

**«Порт 8001 уже занят»** — выберите другой через `-p 8002` и его же укажите в 3x-ui.

**«Порт 443 уже занят другой программой»** (режим 1) — на 443 уже что-то работает, например другой VPN или веб-сервер. Остановите его или выберите другой порт, например `8443`.

**«Установщик 3x-ui завершился с ошибкой»** — последние строки лога показаны на экране, полный лог в `/var/log/selfsteal-3x-ui-install.log`. Чаще всего это временная проблема с доступом к GitHub — запустите скрипт ещё раз.

**«Панель установлена, но подключение не создано автоматически»** — скрипт напечатает адрес панели, логин, пароль и значения, которые нужно вписать вручную. Обычно так бывает, если новая версия 3x-ui поменяла API.

**Панель не открывается в браузере** — порт панели закрыт файрволом у хостера. Откройте его в панели хостера (номер порта — в адресе панели).

**После правки в 3x-ui `openssl` показывает ошибку или старый сертификат** — проверьте, что Target именно `127.0.0.1:<порт>`, а SNI совпадает с доменом. Если всё верно, перезапустите xray: в панели кнопка **Restart Xray**.

**Клиенты не подключаются** — в клиенте не обновилась подписка, и он стучится со старым SNI. Обновите подписку вручную. В режиме 1 также проверьте, что порт VPN открыт у хостера.
